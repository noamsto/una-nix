# una-nix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Nix repo that builds UNA Watch apps to `.uapp` artifacts on x86_64-linux and aarch64-darwin, with a devShell, host tests, and a TouchGFX simulator, consuming `UNAWatch/una-sdk` as a pinned source-only input.

**Architecture:** flake-parts, one module per concern under `nix/`. A patched SDK tree is realized once as `packages.una-sdk-src` and exported to every consumer through `UNA_SDK`. `lib.mkUnaApp` turns an app directory into a `.uapp` derivation; the devShell's `una-build` wrapper runs the identical configure flags so interactive and sandboxed builds cannot diverge.

**Tech Stack:** Nix (flake-parts), CMake, nixpkgs `gcc-arm-embedded` 15.2, Python (`pyelftools`, `pillow`), GoogleTest, SDL2 + Ruby (simulator only).

**Spec:** `docs/superpowers/specs/2026-07-29-una-nix-design.md`
**Issue:** https://github.com/noamsto/una-nix/issues/1

## Established facts

Verified during investigation. Do not re-derive; do not assume otherwise.

- The Alarm example builds to a valid `.uapp` on aarch64-darwin with nixpkgs
  `gcc-arm-embedded` 15.2.rel1. No ST toolchain is needed.
- `-fcyclomatic-complexity` (`cmake/una-app.cmake:52`) is the only blocker.
- The build needs **no host C compiler** — it was proven under `mkShellNoCC`.
  Use `stdenvNoCC` throughout so the host cc-wrapper cannot inject flags into
  the ARM cross-compile.
- `Tests/Host/CMakeLists.txt:85-88` already links `GTest::gtest_main` and
  `GTest::gmock`, the exact targets nixpkgs `gtest` exports.
- Confirmed nixpkgs attributes: `gcc-arm-embedded` (15.2.rel1), `gtest` (1.17.0),
  `SDL2_image` (2.8.12), `rubyPackages.nokogiri` (1.18.10).
- `Examples/Apps/Alarm` is 3.4 MB / 220 files — small enough to vendor.

## File structure

| Path | Responsibility |
|---|---|
| `flake.nix` | Inputs, systems, module imports. No logic. |
| `nix/sdk.nix` | `packages.una-sdk-src`, `unaPython`; exports both as module args |
| `nix/lib.nix` | `mkUnaApp` builder; exported as a module arg and as `flake.lib` |
| `nix/apps.nix` | `packages.hello` — the seed app |
| `nix/devshell.nix` | `devShells.default` and the `una-build` wrapper |
| `nix/checks.nix` | `checks.host-tests` and `checks.hello-uapp` |
| `nix/simulator.nix` | `packages.sim-hello`, x86_64-linux only |
| `patches/0001-cyclomatic-complexity-opt-in.patch` | Makes the ST-only flag opt-in |
| `patches/0002-host-tests-find-gtest.patch` | `FetchContent` → `find_package(GTest)` |
| `apps/hello/` | Seed app, vendored from `Examples/Apps/Alarm` |

## Task 2: Patched SDK tree

**Files:**
- Create: `patches/0001-cyclomatic-complexity-opt-in.patch`, `nix/sdk.nix`

Rationale for the patch shape: `una-app.cmake` is included *before* `project()`
in every app's `CMakeLists.txt`, so CXX is not enabled yet and
`check_cxx_compiler_flag` cannot run reliably at that point. An `option()`
defaulting to `OFF` needs no compiler probe, works before `project()`, and is
the same change we propose upstream in Task 8.

- [ ] **Step 1: Write `patches/0001-cyclomatic-complexity-opt-in.patch`**

```diff
--- a/cmake/una-app.cmake
+++ b/cmake/una-app.cmake
@@ -20,6 +20,13 @@

 endif()
 
+# -fcyclomatic-complexity exists only in ST's GNU Tools for STM32 fork; mainline
+# arm-none-eabi-gcc rejects it outright. Opt-in because this file is included
+# before project(), so no compiler probe is available to detect the fork.
+option(UNA_ENABLE_CYCLOMATIC_COMPLEXITY
+    "Emit cyclomatic complexity metrics (ST GNU Tools for STM32 only)" OFF)
+set(UNA_CYCLOMATIC_COMPLEXITY_FLAGS "")
+if(UNA_ENABLE_CYCLOMATIC_COMPLEXITY)
+    set(UNA_CYCLOMATIC_COMPLEXITY_FLAGS -fcyclomatic-complexity)
+endif()
+
 # Common toolchain setup
 set(CMAKE_TOOLCHAIN_FILE "$ENV{UNA_SDK}/cmake/toolchain-arm-none-eabi.cmake")
 
@@ -49,8 +56,7 @@
     -nostdlib
     -mthumb
     -ffunction-sections
-    -fcyclomatic-complexity
-
+    ${UNA_CYCLOMATIC_COMPLEXITY_FLAGS}
```

- [ ] **Step 3: Write `nix/lib.nix`**

```nix
{ ... }:
{
  perSystem = { pkgs, config, ... }: {
    _module.args.mkUnaApp =
      { pname, version, src, cmakeDir }:
      pkgs.stdenvNoCC.mkDerivation {
        inherit pname version src;

        nativeBuildInputs = [
          pkgs.cmake
          pkgs.gnumake
          pkgs.gcc-arm-embedded
          config.unaPython
        ];

        # The SDK ships its own ARM toolchain file and drives configure itself;
        # nixpkgs' cmake hook would configure the wrong directory.
        dontUseCmakeConfigure = true;

        UNA_SDK = config.unaSdk;

        buildPhase = ''
          runHook preBuild
          cmake -G "Unix Makefiles" \
            -S ${cmakeDir} -B build \
            -DBUILD_VERSION=${version} \
            -DUNA_PYTHON_EXECUTABLE=${config.unaPython}/bin/python3
          cmake --build build
          runHook postBuild
        '';

        installPhase = ''
          runHook preInstall
          mkdir -p $out
          find . -name '*.uapp' -exec cp {} $out/ \;
          runHook postInstall
        '';
      };
  };
}
```

`-DBUILD_VERSION` makes `una_app_setup_version` return early instead of shelling
out to `una-version.sh`, which fails on `git config --global` in the sandbox.
`-DUNA_PYTHON_EXECUTABLE` stops `find_program` from caching a stale store path.

## Task 4: devShell and `una-build`

- [ ] **Step 1: Write `nix/devshell.nix`**

```nix
{ ... }:
{
  perSystem = { pkgs, config, ... }:
    let
      una-build = pkgs.writeShellApplication {
        name = "una-build";
        runtimeInputs = [
          pkgs.cmake
          pkgs.gnumake
          pkgs.gcc-arm-embedded
          config.unaPython
        ];
        text = ''
          cmake_dir=''${1:?usage: una-build <app-CMake-dir> [version]}
          version=''${2:-0.0.0-dev}

          cmake -G "Unix Makefiles" \
            -S "$cmake_dir" -B "$cmake_dir/build" \
            -DBUILD_VERSION="$version" \
            -DUNA_PYTHON_EXECUTABLE=${config.unaPython}/bin/python3
          cmake --build "$cmake_dir/build"
        '';
      };
    in
    {
      devShells.default = pkgs.mkShellNoCC {
        packages = [
          pkgs.cmake
          pkgs.gnumake
          pkgs.gcc-arm-embedded
          config.unaPython
          una-build
        ];

        UNA_SDK = config.unaSdk;
      };
    };
}
```

## Task 7: TouchGFX simulator (x86_64-linux only)

**Files:**
- Create: `nix/simulator.nix`

This is the only task that cannot be validated on aarch64-darwin. Run it on a
thinkpad. The reference recipe is upstream's
`.github/workflows/linux-simulator.yml`.

- [ ] **Step 1: Write `nix/simulator.nix`**

```nix
{ ... }:
{
  perSystem = { pkgs, config, lib, system, ... }:
    lib.optionalAttrs (system == "x86_64-linux") {
      packages.sim-hello = pkgs.stdenv.mkDerivation {
        pname = "sim-hello";
        version = "0.1.0";
        src = ../apps/hello;

        nativeBuildInputs = [
          pkgs.gnumake
          pkgs.autoPatchelfHook
          pkgs.ruby
          pkgs.rubyPackages.nokogiri
        ];

        buildInputs = [
          pkgs.SDL2
          pkgs.SDL2_image
          pkgs.stdenv.cc.cc.lib
        ];

        UNA_SDK = config.unaSdk;

        # The vendored TouchGFX asset converters are prebuilt ELF64 binaries
        # from the Ubuntu 16.04 era; autoPatchelfHook only reaches files in the
        # build tree, so copy them in before it runs.
        postUnpack = ''
          mkdir -p $NIX_BUILD_TOP/touchgfx-tools
          cp ${config.unaSdk}/ThirdParty/touchgfx/framework/tools/imageconvert/build/linux/imageconvert.out \
             ${config.unaSdk}/ThirdParty/touchgfx/framework/tools/fontconvert/build/linux/fontconvert.out \
             $NIX_BUILD_TOP/touchgfx-tools/
          chmod +w $NIX_BUILD_TOP/touchgfx-tools/*.out
        '';

        buildPhase = ''
          runHook preBuild
          make -f Software/Apps/TouchGFX-GUI/simulator/gcc/Makefile -j$NIX_BUILD_CORES
          runHook postBuild
        '';

        installPhase = ''
          runHook preInstall
          mkdir -p $out/bin
          cp Software/Apps/TouchGFX-GUI/build/bin/simulator.out $out/bin/sim-hello
          runHook postInstall
        '';
      };
    };
}
```

- [ ] **Step 2: Build it on a thinkpad**
